# Application Compilation — End-User Ladder

*Zero to Hero hackathon — full plan. From "I found some source code and a README from 2009" to a reproducible, optimised build. Exemplar: **sacct-reporter-classic**, a hand-authored C "2009 edition" forked from the real Alces-Sacct-V2 gem (the ladder's punchline: the modern descendant you already ship). Rung titles echo the brief's napkin rungs word-for-word.*

---

## The ladder in one breath

A stranger arrives holding a tarball and its 2009 README. By rung 5 they have built, measured, and reproducibly re-built a working HPC tool — and written the instructions that let someone else do the same. Six lies are planted, one per rung; catching each is a rung's engine, not an obstacle.

---

## Constraints that shape everything

- **60–90 minutes for six rungs ≈ 12–15 minutes per rung**, including reading and being stuck.
- **Every build step ≤ 2 minutes single-core.** Being stuck must never compete with a compile clock.
- **Curated, not real-era projects:** real `gcc` / `make`, real compile pipeline, but authored source — the error surface is finite and every failure is in the error oracle. Brief rule 7 (*actual experience, not spoofed*) is satisfied: toolchain and compiles are real; only the provenance is authored.

---

## The four decisions to lock first

- [ ] **1. The environment (load-bearing).** Ship a container (or per-climber VM), not the stranger's laptop. Container recipe: gcc present, **zlib dev headers NOT preinstalled** (rung 2's trap must survive boot), a **local vendored package cache** so `dnf provides` works offline. If the venue provides per-climber boxes with a module system, use those; reset = `rm -rf sandbox && untar fresh-sandbox`. Decide arch up front (x86_64; check multi-arch or lock ARM climbers out explicitly).
- [ ] **2. The exemplar = the fork.** `Sacct-reporter-classic-v1.0.0 2009/` is a **fresh git repo** — the gem's clone history has been dropped; the real gem stays untouched on GitHub (AdamJ2009/Alces-Sacct-V2, currently 1.1.1), which is the fiction's living descendant. The classic tree gets **one initial commit dated 2009**, tagged `classic-1.0.0` — that single commit is the freeze everything (trap ledger, line numbers, tarball) derives from. Reference material parked at `trainer/reference/` (gem README + Gemfile.lock), so the classic dir itself ships clean.
- [ ] **3. Win verification.** A `check.sh <n>` per rung prints a visible PASS banner only when something *actually runs* — compile-success ≠ link-success ≠ run-success. `env-check.sh` (rung 0) deliberately verifies only toolchain + sandbox integrity — it must not touch zlib.
- [ ] **4. Hints before polish.** Per-rung hint cards at three depths (1: where to look → 2: name the cause → 3: the exact fix), plus a one-page **error oracle**: exact first-line error text → cause → fix. Self-serve; no hint costs the climber their state.

## The exemplar: sacct-reporter-classic

**What it is (shape, not code):** ~300–500 lines of C across three files — a driver, a sacct-row parser/reporter, and a metrics aggregator — reading pipe-separated sacct-shaped records (JobID, User, Partition, State, Elapsed, TotalCPU) from `.csv.gz` and emitting a metric text report or CSV. Deliberately **hand-rolled 2009 Makefile, no autoconf**: no build-system magic, so every compiler invocation is visible to the climber from rung 1.

**The fiction, kept honest:** the 2009 README may only contain 2009 truth — *except* the rung-3 lie, a deliberate anachronism (usage docs leaked backwards from the Ruby descendant). The ladder states up front that six lies are planted, so anachronisms read as the game, not as sloppiness. The real gem is never linked from inside the fiction; it surfaces in the rung-5 pointer card and the debrief.

**Data (shipped pre-made; generated by `trainer/gen-jobs.py` — deterministic, seed 2009, xorshift32, no embedded filename in the gzip header):**
- `jobs-small.csv.gz` — 1,000 rows (18 users × 4 partitions) → correctness path; expected report checksum lives in ledger RL4
- `jobs-bench.csv.gz` — 1,000,000 rows (255 users × 6 partitions, one short of the cap) → rung 4 wall-clock bench; shape chosen by measurement (−O0 0.92 s vs −O2 0.54 s user time; a 400k draft gave only 1.5× with a sub-0.1-s gap — invisible on a workshop box)
- Byte-identical across runs and paths; full sha256 digests in ledger RL4.

**Keep vs. invent:** the name, report/CSV output format, SLURM vocabulary and Alces lineage are carried over; only the C core, the two data files, and the lying README are authored new.

## The rungs

### Rung 0 — "I found some source code and a README that lies" (5 min)
You arrive holding exactly that: the tarball and its 2009 README (demanding gcc 4.1, citing a package that never existed, claiming zero dependencies).

- Learn `pwd` / `ls` / cd; run `env-check.sh` → green banner (toolchain + sandbox only).
- Hook: **"Six lies are planted. One per rung."**
- One glossary card: *compiler / linker / library / make*.
- Framing that pays off all rung: **"The README is a suspect, not documentation."**

**Win:** PASS banner + climber names one lie aloud.

### Rung 1 — build a hello-world from source (10 min)
The README says "just run `./build.sh`" — no such file exists.

- Fall back to real basics: `gcc hello.c -o hello && ./hello`; the hello file prints the *sacct-reporter 1.0* banner — identity lands in rung 1.
- Gentle trap only: wrong path / missing exec bit.

**Win:** the banner prints.

### Rung 2 — hunt dependencies: toolchains, flags, the things the README neglected (15 min)
Two hunts, one rung.

- **Toolchain first:** README demands gcc 4.1; the climber picks what's actually available — `module av compiler` on HPC — and writes pins line 1 *(the pins file: one line per rung, the reproducibility contract grows as you climb)*.
- **Packages second:** README says `yum install sacct-metrics-devel` — never existed (and claims "no third-party dependencies" — lie #3). Transferable move: `dnf provides '*/zlib.h'`; the header installs; compilation proceeds.

**Cascade note (deliberate):** once the header is found, gcc's *next* complaint is old-style-function errors — those are rung 3's territory. `check.sh 2` asserts "past the header, not yet linked" and shows the banner, so climbers don't chase them here.

**Win:** make stalls on `metrics.c`, not on zlib; pins line 2 adds zlib.

### Rung 3 — build something real, and keep it working (20 min)
Build the tool against the shipped data — the cascade, in strict order:

1. **K&R definitions refuse modern gcc defaults** → add `-std=gnu89` to CFLAGS.
2. Then the **link fails** — `undefined reference to inflate` → `pkg-config --libs zlib` → `-lz`.
3. Anachronism lie: README usage says `sacct-reporter report…`; the make target is actually `acsacct` — and the binary's own `usage()` prints the descendant's syntax (see ledger).
4. Reading the **first** error at every step; the truth test `make clean && make` — *keep it working means it survives a pristine rebuild*.

**Win:** the report on `jobs-small` matches the expected checksum; pins line 3 records `-std=gnu89` + the link flags.

### Rung 4 — optimise the build: what am I leaving on the table? (15 min)
`bench.sh` is provided; README lies: "any optimisation beyond -O2 is pointless."

- Fill the timing table: `-O0 → -O2 → -O3 → -march=native` on the 1M-row bench (reference box: −O0 0.9 s → −O2 0.5 s).
- Lesson card: `make -j$(nproc)` makes the *build* faster; flags make the *program* faster.
- HPC twist card: `-march=native` breaks on heterogeneous cluster nodes — performance vs portability.
- Pointer card (optional, not required to pass): LTO / PGO — on this zlib-I/O-bound bench expect ≈ −O2, and that null is the honest finding.

**Win:** completed table + `-O2` clearly faster than `-O0` (≥ 1.5×; reference box 1.7×) with checksum-identical reports, explained in one sentence. Pins line 4: final optimisation choice + why.

### Rung 5 — reproducible build: someone else can climb my ladder from my instructions alone (20 min)
Ship the contract: `build.sh` + the pins file + `BUILD-REPRO.md` (pinned compiler version, flags, data files, order).

- **Verified live:** hand the instructions to the climber next to you → they build in a fresh sandbox → report checksums match. Rung 5 is self-testing.
- Pointer card: `Gemfile.lock` is the same contract when nothing compiles — full circle to the real descendant gem.

**Total budget: ~85 minutes.**

## Stuck-proof

- **Error oracle** (one page, climber greps the *first* line of their error). Draft rows now, freeze wording after the dry-run:

| First line of error | Cause | Fix | Rung |
|---|---|---|---|
| `bash: ./build.sh: No such file or directory` | The README lied | Compile it yourself: `gcc hello.c -o hello` | 1 |
| `gcc: command not found` / README's `gcc 4.1` vs your `gcc --version` | Stale toolchain assumption | Pick an available compiler; record in pins | 2 |
| `fatal error: zlib.h: No such file or directory` | Dev headers absent; package renamed since 2009 | `dnf provides '*/zlib.h'` → install | 2 |
| `undefined reference to 'inflate'` (etc.) | Link order / missing `-lz` | `pkg-config --libs zlib` → add the flag | 3 |
| `./sacct-reporter: No such file or directory` | Anachronism lie | `make`'s target list; it's `acsacct` | 3 |
| Old-style-function / `expected declaration specifiers` errors | K&R code vs modern gcc default | `-std=gnu89` | 3 |
| Bench slower than expected | Beyond -O2 *is* not pointless | Fill the table; measure, don't guess | 4 |

- **Hint cards:** 3 depths per rung; depth-1 never names the answer; nothing costs the climber their state.

## Visible climb, front door, reset

- After every `check.sh` PASS: banner — *"RUNG n/5 ✓ — you just built a working binary from a lying README."*
- **Front door (four lines):** get the sandbox → run `env-check.sh` → open rung 1 → where the climb log lives.
- **Reset is one command off the front door** (fresh container / `reset-sandbox` untar on provided boxes), returning everything to rung 0. All rung state lives inside the sandbox; nothing leaks between climbers.

---

## Tutorialising the lines (trap-ledger pipeline)

Only *trap lines and read-lines* get tutorialised — the `zlib.h` include, the K&R prototypes, the Makefile link command, the make target, the report format: a ledger of ~10–15 rows, never a line-by-line walkthrough.

1. **Freeze first.** Traps land as one commit; tag it (`classic-1.0.0`). Capture every line number from that tag **by function name + line**, so minor edits don't rot the tutorial.
2. **One ledger, four outputs.** `trainer/trap-ledger.md` is the single source of truth: each row = trap id (T1…) · file + function + frozen line · 2–3-line snippet · rung · *verbatim* first-line error text · hint depths 1–3 · consuming artifact. The rung-card beat, the three hint depths, the oracle row and the `check.sh` assertion all derive from the same row — nothing drifts.
3. **Capture the error text empirically.** Build once in the sandbox with each trap live and copy the *first* real gcc/ld line into the ledger. Never author compiler messages from memory — they vary by version and that's exactly how oracles rot.
4. **Climber material never cites source lines.** The oracle greps the error *string*; hints never say `file:line`. Depth-1 teaches where to *look*, depth-2 names the cause, depth-3 gives the exact fix.
5. **`trap-check.sh` — the ladder's own CI.** Walk the ledger: fresh checkout of the tag, hit each failure point, assert the expected line appears in the output. Rerun after every edit; doubles as the oracle's text-regenerator.
6. **Packaging split.** Climber tarball = frozen tag minus `trainer/`. The gem's real `README.md` never ships — the authored liar replaces it in the tarball only.

## Build-day plan

**Pre-day (the fork):** author the C core *with its four traps in place* (dead-package README, missing `-lz`, gnu89 K&R code, anachronism usage line); generate + checksum both data files; build the container image; write `build.sh`'s final form for trainer reference.

**Kick-off (~30 min):** brief recap; groups formed; napkin ladder printed; pins-file mechanic agreed; fork hygiene check (ladder dir separate from the gem's real tags/CI).

**Build (~4 h) — bottom rungs first:**
1. `env-check.sh`, `check.sh` per rung, banners — the verification spine first.
2. Rung cards + hint cards written *as each rung stabilises* — never at the end.
3. Error oracle v0 from the planned traps.
4. Front door mid-way, not last.
5. Reset tested end-to-end with a fresh teammate.
6. Blind dry-run at ⅔ pace with the climb log sheet → fix only the top two stalls → freeze oracle wording → re-estimate rung times from the log, not vibes.

**Climb (2–3 h):** rotation between groups; the handover rule stands — reset what you left, clear its front door; collect climb logs (rungs reached, hints taken by depth, stalls + why, one-sentence surprise).

**Debrief:** each group reads back its collected logs: what stalled, what fixed it, what they'd change. Debrief flex: hand climbers the six lies and ask them to classify — *fabricated* (build.sh never existed even in 2009; the package never shipped anywhere), *stale truth* (gcc 4.1 was real frontend guidance in 2009; "BUGS: None" was true in its era), *aged opinion* (-O2 grump). Punchline to land: most of the README wasn't lying — it was rotting; the skill is noticing when a truth expired.

## Risk watchlist

- **C-authoring time** (gnu89 code takes longer to write than to climb) → prep before the day; fallback: single-file ~200-line core with three traps (dead package, `-lz`, gnu89) and rung 4's bench trimmed.
- **Offline venue** → vendored package cache baked into the image; sources and data shipped in it.
- **Compile-time creep** → re-vet the 2-minute rule before freezing.
- **Arch mismatch** → multi-arch image or explicit arch line on the front door.
- **Rung 5 needs a second human** → pair climbers at rung 5; fallback: fresh-container test with a logged result.
- **Fork hygiene** → the classic dir must not pollute the gem's real tags, changelog or CI.
